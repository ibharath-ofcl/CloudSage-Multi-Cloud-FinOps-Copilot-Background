# CloudSage Safe Analytical Query Planning

## 1. The Zero-Raw-SQL Architecture

A major vulnerability in LLM-assisted database systems is the execution of unvalidated, dynamic SQL generated by an LLM ("text-to-SQL"). Such architectures introduce SQL injection risks, table scan DoS vectors, and uncontrolled schema leaks.

CloudSage adopts a **strictly deterministic query planning architecture**:
1. The LLM is **never** asked to generate SQL.
2. The user prompt and extracted entities are mapped to a structured, schema-validated `QueryPlan`.
3. The query plan is executed strictly through parameterized SQLAlchemy ORM statements.
4. Every dataset, field, aggregation, and filter is strictly validated against an immutable **Allowlist**.

## 2. QueryPlan Structure

```python
class QueryPlanSchema(BaseModel):
    intent: str
    target_dataset: str
    filters: Dict[str, Any]
    aggregations: List[str]
    group_by: List[str]
    time_range: Dict[str, Any]
```

{

## 3. Strict Allowlists

### Allowed Datasets (`ALLOWED_DATASETS`)
- `billing_records` (FOCUS 1.0 Normalized Billing)
- `cloud_resources` (Stage 5 Multi-Cloud Inventory)
- `waste_detections` (Stage 6 Waste Detection Engine)
- `cost_anomalies` (Stage 7 Cost Anomaly Detection Engine)
- `recommendations` (Stage 8 Advisory Recommendation Engine)

### Allowed Aggregations (`ALLOWED_AGGREGATIONS`)
- `SUM`: Evaluates exact numeric aggregates on cost, savings, or usage quantities.
- `COUNT`: Evaluates record and incident frequencies.
- `AVG`: Evaluates mean expenditure or baseline rates.
- `MIN`: Evaluates floor values.
- `MAX`: Evaluates peak cost spikes.

### Allowed Grouping Fields by Dataset
| Dataset | Permitted Grouping Dimensions |
| :--- | :--- |
| `billing_records` | `provider`, `service_name`, `region`, `pricing_model`, `usage_start_time` |
| `cloud_resources` | `provider`, `resource_type`, `region`, `status` |
| `waste_detections` | `provider`, `waste_type`, `severity`, `status` |
| `cost_anomalies` | `provider`, `anomaly_category`, `severity`, `status` |
| `recommendations` | `provider`, `strategy_id`, `priority`, `status`, `action_type` |

## 4. Query Execution & The Zero Float Rule

In compliance with CloudSage FinOps engineering standards:
- **Zero Float Rule**: All aggregations use PostgreSQL `Numeric(18, 4)` and Python `Decimal`. Floating-point arithmetic (`float`) is strictly prohibited in monetary pipelines.
- **Limit Caps**: Query plans enforce deterministic pagination and limit thresholds (e.g. `limit=10` or `limit=30`) to avoid excessive memory consumption.
- **Parameterized Filters**: All filters are passed as bound parameters to SQLAlchemy ORM models, eliminating SQL injection.
